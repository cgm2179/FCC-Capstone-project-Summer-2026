# 7th-Floor 3D model — vector (contour) build

Generated by [`../build_model_vector.py`](../build_model_vector.py). This is a
higher-fidelity sibling of the box build in [`../model_3d/`](../model_3d/).

**What's different from `model_3d/`.** Both start from the same
`material_grid.npy` and the same classification (`build_masks` + `PARTS_SPEC`),
so **materials, heights, colors and the georeference are identical**. The box
build extrudes greedy axis-aligned rectangles (stair-steps every diagonal and
curve); this build **vectorizes each material region** (marching-squares
contours + Douglas–Peucker) and extrudes true polygons into **watertight,
per-material solids**. The curved lunch-room glass, the round conference core
and angled offices come out smooth, and the meshes are solid (top + bottom
caps), which matters for STL and for clean CAD import.

> Note on the downloaded shapefiles (`floorplan_7th_floor_v2`): they are a finer
> vector trace, but from a **different source image** than the grid, and they do
> not co-register to it (wall overlap maxes out ~0.30 IoU — nonlinear bay-spacing
> difference), and their own material labels are coarse (~91 % "cubicle"). So the
> reliable way to get *vector geometry + correct materials* is to vectorize the
> grid, which is what this build does.

## DWG (no direct writer — convert from DXF)

DWG is a proprietary binary format with no faithful open/Python writer. The DXF
above is the accurate source; convert it with any of:

- **ODA File Converter** (free, Open Design Alliance): set input *DXF*, output
  *DWG*, pick your AutoCAD version, Convert. CLI form:
  ```bash
  ODAFileConverter <in_dir> <out_dir> "ACAD2018" "DWG" "0" "1" "floor7v_model.dxf"
  ```
- **AutoCAD / BricsCAD**: `Open` the DXF, then `SAVEAS` → *DWG*.

Layers and colors survive the round-trip (one layer per material, ACI colors).

## SKP (no direct writer — import into SketchUp)

SketchUp's format is proprietary; import a neutral format and save:

1. SketchUp → **File ▸ Import** → choose `floor7v_model.dae` (Collada) — or the
   DXF (SketchUp Pro). In the importer options, units are **feet**.
2. It comes in as grouped, per-material geometry with the right colors (glass is
   translucent).
3. **File ▸ Save As** → `.skp`.

(For scripted conversion, SketchUp's Ruby API `Sketchup.active_model.import`
then `.save` does the same headlessly.)

## DEM

An indoor "DEM" here is a **height field**: each cell's value is the tallest
structure top at that spot, in **meters** (0 where only floor/air). `.tif` is
georeferenced to EPSG:3857 via the worldfile (`.tfw`, includes the ~7.3° map
rotation) so it overlays a web basemap; the height *values* are true meters
(horizontal 3857 lengths are inflated ~1.285× at this latitude, per
`floorplan_meta.json`). `.asc` carries the same values in the model's own pixel
grid for tools that want plain ASCII.

## Regenerate

```bash
python3 STEP_1/build_model_vector.py            # feet (default)
python3 STEP_1/build_model_vector.py --unit meters
```

Refine the model by editing `STEP_1/material_overrides.json` (materials) or
dropping rectangles into `STEP_1/model_3d_vector/cubicle_zones.json` /
`wall_zones.json` (5 ft vs 9 ft orange split) — this build reads them via the
same `build_masks` the box build uses. Furniture is ~73 % of the triangles; if
you want a lighter walls-only model, comment `furniture_desk` out of
`PARTS_SPEC`.
